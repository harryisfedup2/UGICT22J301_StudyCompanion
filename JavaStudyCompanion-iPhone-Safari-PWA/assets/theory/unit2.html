A short design history: what Java adopted and shaped

Classes, objects, inheritance, and exception handling did not begin with Java; they developed across earlier programming languages and software research. Java's historical contribution was to bring a carefully specified, class-based object model together with portability goals, managed memory, access control, and a standard library in one general-purpose platform. This helped developers move from small programs to reusable components that could be distributed and run on compatible virtual machines.

The original Java Language Specification describes Java as class-based and object-oriented, and explains that Oak was designed for embedded consumer electronics before being retargeted to the Internet. Java chose single inheritance for classes, with interfaces as a separate way to share contracts. Later language evolution added nested type declarations and richer library support while emphasizing compatibility with existing code. These choices explain why the syllabus treats a class, access boundary, superclass, and package as related tools rather than isolated keywords.

Arrays, input, output, and error streams

An array is a fixed-length object whose elements all have the same component type. Its index begins at zero, and its length is available through the field length. An array variable is a reference, so it can be null; newly allocated numeric elements start at zero, booleans at false, and reference elements at null.

int[] marks = {82, 91, 76};        // one-dimensional array
int[][] seats = {{1, 2}, {3, 4}}; // two-dimensional array-of-arrays
int[][] jagged = new int[2][];     // rows are separately allocated
jagged[0] = new int[3];
jagged[1] = new int[1];
System.out.println(marks.length);  // 3

Java's two-dimensional arrays are arrays whose elements are references to row arrays. Rows can have different lengths (a ragged array), so check matrix[row].length for the selected row. Arrays are appropriate for known-size collections and efficient indexed access; use collection classes when the number of elements changes dynamically.

Console I/O

System.out is the usual output stream; System.err is a separate conventional stream for diagnostics. Scanner can parse human input but has token and locale rules; BufferedReader reads lines efficiently. Input can fail or be malformed, so production code validates it and handles exceptions.

import java.util.Scanner;

class ReadAge {
    public static void main(String[] args) {
        try (Scanner input = new Scanner(System.in)) {
            System.out.print("Age: ");
            if (input.hasNextInt()) {
                int age = input.nextInt();
                System.out.println("Next year: " + (age + 1));
            } else {
                System.err.println("Please enter a whole number.");
            }
        }
    }
}

Line by line: the import makes the library class available by its short name. main is the program entry point. The try-with-resources statement arranges for the scanner to close. The prompt is printed, hasNextInt checks the next token before parsing, and the two branches print either a computed value or a clear diagnostic. A reusable program should consider whether it owns standard input before closing a scanner around it.

Expected interaction: entering 20 prints Next year: 21; entering twenty prints Please enter a whole number. to the error stream.

Control statements, loops, and typecasting

  • if / else selects among branches using a boolean expression. Use braces even for one-statement branches to make edits safer.
  • switch selects among cases. Traditional switch statements can fall through without break; arrow-style switch rules avoid that behavior in supported Java versions.
  • for is useful when initialization, condition, and update form a counted loop; enhanced for walks each array or iterable element.
  • while checks a condition before each iteration; do-while checks after the body and therefore runs at least once.
  • break exits a loop or switch; continue skips to the next iteration. Labeled forms exist but can make flow harder to follow.
  • return exits a method and may provide its result.

Type casting converts a value or reference to another type under defined rules. Primitive narrowing can lose data; reference casts can fail at runtime if the object is not compatible. Prefer instanceof when a reference cast is not guaranteed by the program's design.

Classes, objects, constructors, and member kinds

A class declares fields, methods, constructors, and nested types. An object is one instance with its own instance fields. new allocates an object and invokes a constructor. A constructor has the class name, has no return type, and establishes the object's valid starting state.

Constructor overloading means declaring constructors with different parameter lists. A no-argument constructor is generated only if a class declares no constructors. this(...) invokes another constructor in the same class and must be its first statement; super(...) invokes a superclass constructor and must also be first. If neither is written, Java inserts super() when the superclass has an accessible no-argument constructor.

Method overloading uses the same method name with different parameter lists. The compiler chooses an overload using compile-time argument types; changing only a return type does not create a valid overload. Overloading is distinct from overriding.

Inheritance lets a subclass extend one superclass using extends. Java classes support single inheritance; multilevel and hierarchical arrangements are possible. There is no multiple inheritance of classes, which avoids ambiguous inherited implementations; multiple interfaces can express multiple contracts. A subclass constructor uses super to initialize the superclass portion before its own state.

Overriding replaces an inherited instance method with a compatible implementation. Use @Override so the compiler catches spelling/signature mistakes. A static method is hidden, not overridden; private methods are not inherited as overridable methods; constructors are never overridden. The runtime object's class chooses an overridden method during dynamic method dispatch, even if the variable is declared as a superclass type.

An abstract class cannot be instantiated directly and can combine state, implemented methods, and abstract methods without bodies. A concrete subclass must implement inherited abstract methods. Abstract classes are useful when related types share real state or partial behavior. The root class Object supplies common methods such as toString, equals, hashCode, and monitor methods; classes inherit from it directly or indirectly unless they are the special root declaration itself.

Nested and inner classes

A nested class is declared inside another class. A static nested class does not need an enclosing object; a non-static member class (often called an inner class) is associated with an instance of its enclosing class. Local and anonymous classes can be declared inside methods or expressions. They help group implementation details near the code that uses them, but over-nesting can make a design harder to navigate.

Complete example: constructors, array, override, dispatch, and nested type

class CourseMember {
    private final String name;
    static int count = 0;

    CourseMember(String name) {
        this.name = name;
        count++;
    }

    void introduce() {
        System.out.println("Member: " + name);
    }
}

class Student extends CourseMember {
    private final int[] marks;

    Student(String name, int[] marks) {
        super(name);
        this.marks = marks.clone();
    }

    @Override
    void introduce() {
        int total = 0;
        for (int mark : marks) total += mark;
        System.out.println("Student total: " + total);
    }
}

public class Unit2Example {
    static class Badge {
        final String label;
        Badge(String label) { this.label = label; }
    }

    public static void main(String[] args) {
        CourseMember person = new Student("Mira", new int[]{80, 90});
        person.introduce();
        System.out.println("Created: " + CourseMember.count);
        Badge badge = new Badge("JAVA");
        System.out.println("Badge: " + badge.label);
    }
}

Line by line: CourseMember defines a general type. Its private final name is initialized by the constructor; the static counter is shared by all members. The constructor's this.name distinguishes the field from its parameter. Student extends CourseMember specializes the member and adds an array. Its constructor calls super(name) first, then clones the input array so a caller cannot change the stored marks through the original array reference. @Override marks a replacement implementation. The enhanced for-loop totals each mark. person is declared as the parent type but refers to a Student, so runtime dispatch calls Student's introduce. The static nested Badge type groups a small helper with the example class.

Expected output:
Student total: 170
Created: 1
Badge: JAVA

Abstract class syntax

abstract class Shape {
    abstract double area();
    void describe() { System.out.println("A shape"); }
}
class Circle extends Shape {
    private final double radius;
    Circle(double radius) { this.radius = radius; }
    @Override double area() { return Math.PI * radius * radius; }
}

Shape defines a required operation plus reusable behavior. Circle provides the missing formula; callers can use a Shape reference for different concrete shapes.

Packages, access protection, and imports

A package groups related types, provides a namespace, and participates in access control. A source file's optional package declaration comes before imports and type declarations. The directory structure convention mirrors the package name, for example edu.example.course maps to folders edu/example/course. Build tools and the class path/module path tell the compiler and runtime where packages are found.

package edu.example.course;

import java.util.Arrays;

public class Roster {
    public static void main(String[] args) {
        System.out.println(Arrays.toString(new String[]{"Mira", "Asha"}));
    }
}

The import declaration lets code use a type's simple name; it does not copy code or load a package on its own. java.lang is imported implicitly. A wildcard import brings accessible types from one package into scope, not its subpackages. Public top-level types are normally placed in a correspondingly named source file. Package-private types are visible only in their package.

Common errors, uses, and design choices

  • Using an array index outside 0 through length - 1 causes ArrayIndexOutOfBoundsException.
  • Confusing array.length with a method call; String uses length(), while arrays use a field.
  • Comparing objects with == when content equality is intended.
  • Forgetting that a constructor's first statement must be this(...) or super(...) when explicitly chaining.
  • Assuming every class has a generated no-argument constructor after declaring another constructor.
  • Trying to override a static method, reduce visibility, or change the return type incompatibly.
  • Thinking a final object reference makes the referenced object's fields immutable.
  • Using protected as a general-purpose “public to subclasses” rule without considering package access and cross-package subclass rules.
  • Placing an import before the package declaration or expecting a wildcard import to include subpackages.

Arrays, classes, and packages are useful wherever data has stable structure and behavior: student records, inventory items, drawing shapes, transport systems, or reusable library APIs. Prefer small cohesive classes, private state, clear method contracts, and composition where inheritance does not represent a true subtype.

Viva practice · 40 answered questions

1. What is an array?

An array is a fixed-length object whose elements share one component type. Its elements are reached by zero-based indexes.

2. How is an array length accessed?

Use the field array.length, without parentheses. The length is fixed after the array is created.

3. What is a two-dimensional array in Java?

It is an array whose elements are references to row arrays. Rows may have different lengths, so Java arrays can be ragged.

4. What is the default value of a new int array element?

Zero. Other numeric primitive elements also default to zero, boolean elements to false, and reference elements to null.

5. What happens when an array index is invalid?

The JVM throws ArrayIndexOutOfBoundsException. Valid indexes start at zero and end at length - 1.

6. What is the difference between System.out and System.err?

Both are standard output streams, but System.err is conventionally used for diagnostics. A shell or IDE may display or redirect them separately.

7. What is Scanner used for?

Scanner tokenizes and parses input from sources such as the console. Check the next token or handle parsing exceptions when the input may be invalid.

8. What does try-with-resources do?

It closes each declared resource automatically when control leaves the block, including when an exception occurs, provided the resource implements AutoCloseable.

9. What is an if statement?

It conditionally executes a branch when a boolean expression is true. An optional else handles the false case.

10. What is a switch statement?

It selects among alternatives based on a selector value. Traditional cases may fall through; arrow-style switch rules do not fall through.

11. Compare while and do-while.

while tests before running its body and may run zero times. do-while tests after the body and runs at least once.

12. What does break do?

It exits the nearest enclosing loop or switch statement. A labeled break can exit an enclosing labeled statement.

13. What does continue do?

It skips the remaining work in the current loop iteration and proceeds to the next iteration, subject to the loop's update and condition.

14. What is typecasting?

Typecasting converts an expression to a compatible type. Primitive narrowing can lose information; an invalid reference cast can throw ClassCastException.

15. What is a class?

A class declares a type's state and behavior through fields, methods, constructors, and nested declarations. It describes objects that can be instantiated.

16. What is an object?

An object is a runtime instance with identity, state, and behavior. Each instance normally has its own instance field values.

17. What is a constructor?

A constructor initializes a new object. It has the class name and no return type, not even void.

18. When is a default constructor generated?

The compiler provides a no-argument constructor only when the class declares no constructor. Once any constructor is written, the compiler does not add that default.

19. What is constructor overloading?

It is declaring multiple constructors with different parameter lists. Each can provide a convenient way to create a valid object.

20. What is the purpose of this?

this refers to the current object inside an instance context. It can disambiguate a field from a parameter or invoke another constructor with this(...).

21. What is the purpose of super?

super refers to the superclass portion of the current object. It can invoke a superclass constructor or access an inherited implementation.

22. What is method overloading?

Overloading declares the same method name with different parameter lists. The compiler resolves which overload applies; return type alone cannot distinguish overloads.

23. What is method overriding?

Overriding supplies a compatible implementation of an inherited instance method in a subclass. The runtime object's type determines which implementation runs.

24. Why use @Override?

It asks the compiler to verify that the method really overrides or implements a method. It catches signature mistakes early.

25. What is dynamic method dispatch?

It is runtime selection of an overridden instance method based on the actual object's class, even when the reference is declared as a superclass type.

26. What is single inheritance?

A Java class directly extends at most one other class. It may still implement multiple interfaces.

27. Define multilevel inheritance.

It is a chain of classes where one subclass extends another subclass, such as Vehicle → Bus → SchoolBus.

28. Define hierarchical inheritance.

It occurs when multiple subclasses extend the same superclass, such as Bus and Bicycle extending Vehicle.

29. What is an abstract class?

It is a class that cannot be instantiated directly and may declare abstract methods without bodies. Concrete subclasses complete the required behavior.

30. Can an abstract class have concrete methods?

Yes. It can combine implemented methods and fields with abstract methods that subclasses must implement.

31. What is Object in Java?

java.lang.Object is the root superclass of ordinary Java classes. It defines common methods such as equals, hashCode, and toString.

32. What does static mean for a field?

The field is associated with the class rather than a separate copy per object. All instances access the same class-level field.

33. What does final mean for a reference?

The reference cannot be reassigned after initialization. The object it refers to may still be mutable unless its design also prevents changes.

34. What does a final class do?

A final class cannot be subclassed. This can preserve design invariants or support immutable class designs.

35. Name Java's access levels.

private, package-private (no modifier), protected, and public. Their visibility differs by class, package, and subclass relationship.

36. What is package-private access?

With no access modifier, a member or top-level type is visible to code in the same package but not generally to code in other packages.

37. What is a package?

A package groups related types, creates a namespace, and affects access control. Package names conventionally map to directory paths.

38. What does import do?

An import lets source refer to an accessible type by its simple name. It does not copy source code or automatically import subpackages.

39. What is an inner class?

It is a non-static member class associated with an enclosing object. A static nested class is nested too but does not require an enclosing instance.

40. When should inheritance be used?

Use it when a subtype truly satisfies the superclass contract and can safely be used wherever the parent is expected. For a “has-a” relationship, composition is often clearer.
